XCef SDK 管理

UCefView 动态加载 XCef，CEF 在独立的 XCefHost 进程中运行。每个插件版本固定支持一个 XCef API 版本，可以从 SDK 目录中选择兼容的 CEF 变体。

安装和选择 SDK

打开 **Project Settings > Engine > UCefView Settings > XCef SDK**，刷新目录，下载并安装兼容包，然后选择 **Use for this project**。重启 Editor 后加载所选 SDK。下载不会自动切换项目选择，选择 SDK 也不会触发构建。

安装时检查压缩包完整性、SHA-256、XCef 版本和必需运行文件。无需访问 GitHub 也可以发现本机已安装的包。不同项目可以选择不同包，也可以复用同一安装。

共享安装与项目配置

系统 默认共享根目录
Windows LOCALAPPDATA%/XCef
macOS ~/Library/Application Support/XCef
Linux ${XDG_DATA_HOME:-~/.local/share}/XCef

UCEFVIEW_XCEF_SDK_ROOT 可以覆盖根目录。完整 SDK 保存在 <root>/<平台-架构>/<包名去掉.zip>/。例如 Windows 库位于 <安装目录>/XCef/bin/Win64/XCef.dll。

项目选择保存在 Config/DefaultEngine.ini，应随项目提交。各构建机器在自己的共享根目录安装所选 SDK。Windows 配置为：

[UCefView.XCefSDK.Win64]
Package=<包名去掉 .zip>
Sha256=<包的 SHA-256>

Linux 使用 [UCefView.XCefSDK.Linux]。Mac 使用 [UCefView.XCefSDK.Mac]，配置键为 Package.arm64、Sha256.arm64、Package.x86_64、Sha256.x86_64。只配置项目需要的目标；Mac 通用构建需要两种架构。设置面板显示当前操作系统的包。

Editor 与 Game 加载

目标 运行文件来源 构建行为
Editor、PIE、UnrealEditor -game 所选共享安装 不复制或清理 SDK，Live Coding 也一样
Game 项目的 Binaries/ThirdParty/XCef/<平台[/架构]> 复制所选 SDK，并以 NonUFS 散文件形式打包

Engine 插件和项目插件使用相同机制。Game 构建要求已安装 SDK；UnrealBuildTool 不会下载。打包游戏使用随包分发的文件，不依赖共享缓存或 Editor SDK 管理器。

同一 SDK 可能被多个 Editor 加载。删除或修改前，关闭所有使用它的 Editor。更新项目内游戏运行文件前，关闭正在运行的游戏。

故障处理与升级

  • Editor 缺少 SDK 或不匹配： 在 UCefView Settings 安装/选择兼容 SDK；若安装损坏则重新安装，然后重启。重新编译项目不会修复共享安装。
  • Game 构建缺少 SDK： 在构建机器安装配置指定的目标包，再重新构建和打包；分发时保留完整输出。
  • 旧 Editor 副本： <Project>/Binaries/ThirdParty/Editor/XCef 已不再使用，也不会自动清理。关闭可能仍使用旧插件的进程后，可以删除该目录。
  • 旧强制启动编译设置： 插件会恢复旧流程保存的用户偏好。新的 SDK 选择只要求重启。

.package 标识运行文件所属的 SDK 包。Game 准备阶段在标识缺失或不匹配时清理对应目标目录，标识相同时保留目录。此比较不是完整的文件内容比较。

更新插件支持的 XCef API 版本

头文件

Source/ThirdParty/XCef/include 只保留一份跨平台头文件及 LICENSE。 UCefView 编译时私有包含这些头文件，不再使用 XCef 外部模块、导入库或源码目录中的运行文件。

运行 SDK

发布各系统和架构的完整 SDK 包。更新头文件时，同步更新 UCefViewEditor 固定支持的 XCef 版本及发布目录。 接口变化必须使用新的 XCef 版本号，不要在同一版本下替换不兼容的二进制文件。 Editor 检查版本号、下载完整性和必需运行文件，不再读取或比较头文件。

验证

更新后需要验证插件编译、XCefHost 启动、浏览器渲染及各目标平台的游戏打包和启动。
