输入穿透

UCefView 支持像素级透明输入穿透。启用后，WebView 只会在可见的浏览器像素上消费指针输入。鼠标、触摸、滚轮和拖拽事件如果落在透明像素上，会以 unhandled 的形式返回给 Unreal，使 WebView 后方的 widget 仍能交互。

这适合 HUD、菜单和混合 UI：HTML/CSS 可以覆盖在原生 UMG 或 Slate widget 上方。例如，一个浮动 Web 菜单可以在按钮区域消费点击，而透明区域则把点击传给底层 Unreal UI。

警告
像素级透明输入穿透只要启用就一定会产生性能开销，即使网页本身没有任何透明区域或透明像素。UCefView 仍需要从渲染后的浏览器纹理维护 alpha mask，因此只应在确实需要像素级输入穿透的 view 上启用。

启用功能

UMG

在 UMG 编辑器中选择 UCefView widget，并启用：

  • UCefView::bEnableTransparentInputPassthrough

也可以通过 Blueprint 中生成的 setter 控制：

  • UCefView::SetEnableTransparentInputPassthrough

Slate

构造 SCefView 时传入参数：

SNew(SCefView)
.Url(TEXT("https://example.local/"))
.bEnableTransparentInputPassthrough(true)
SCefView
A Slate widget that embeds a Chromium Embedded Framework (CEF) browser.
定义 SCefView.h:42

或者运行时修改：

MyCefView->SetEnableTransparentInputPassthrough(true);

让网页真正透明

透明输入穿透依赖最终渲染结果中的 alpha 值。网页和 UCefView 背景都必须真正透明。

对于 HTML 内容，确保页面背景没有填满整个浏览器：

html,
body {
background: transparent;
}

对于 UCefView，需要保持配置的背景 alpha 为 0。如果 UCefView 背景是不透明的，整个 view 都会被视为可见，输入不会穿透。

命中测试规则

启用透明穿透后，Slate widget 会在处理输入前检查本地指针位置。检查顺序遵循可见层级：

  1. 如果没有启用透明穿透，view 正常处理输入。
  2. 如果配置的浏览器背景不透明，view 正常处理输入。
  3. 采样主浏览器 frame 的 alpha mask。不透明像素消费输入。
  4. 如果 CEF popup 可见，则在主 frame 之上采样 popup alpha mask。不透明 popup 像素消费输入。
  5. 如果没有任何可见浏览器像素占用该位置，事件会作为 unhandled 返回给 Unreal，后方 widget 可以接收它。

实现说明

Alpha mask 由 FCefSlateTexture 维护。它使用双缓冲 TBitArray<> 存储，只有新的 readback 完成后才会切换当前使用的 mask。无论底层来自 pixel buffer 还是 shared texture，只要转换成 Unreal UETexture2DRHIRef，都会走同一套采样路径。

由于 mask 来自渲染后的纹理，该功能反映的是最终浏览器 alpha 输出，而不是 DOM hit testing。代价是 texture readback 会有成本，因此应只在需要像素级穿透行为的 view 上启用。

常见问题

  • 如果所有点击仍被 WebView 消费，检查网页或 UCefView 背景是否不透明。
  • 如果只有 popup 内容行为异常，确认 popup 渲染结果中确实存在透明像素。
  • 如果某个 view 不需要该功能，应保持关闭，避免不必要的 alpha mask readback。
