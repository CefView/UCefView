XCef SDK Management

UCefView dynamically loads XCef. CEF runs in the separate XCefHost process. Each plugin release supports a fixed XCef API version; choose among compatible CEF variants offered by its SDK catalog.

Install and select an SDK

Open Project Settings > Engine > UCefView Settings > XCef SDK, refresh the catalog, download/install a compatible package, and choose Use for this project. Restart the Editor to load it. Downloading a package does not automatically change the project's selection, and selecting one does not request a build.

Packages are checked for archive integrity, SHA-256, XCef version, and required runtime files. Already installed packages can be discovered locally without GitHub access. Different projects can select different packages or reuse the same installation.

Shared installation and project selection

System Default shared root
Windows LOCALAPPDATA%/XCef
macOS ~/Library/Application Support/XCef
Linux ${XDG_DATA_HOME:-~/.local/share}/XCef

UCEFVIEW_XCEF_SDK_ROOT overrides this root. Each complete SDK is stored at <root>/<platform-arch>/<package-basename>/. For example, the Windows library is <installation>/XCef/bin/Win64/XCef.dll.

Project selections are stored in Config/DefaultEngine.ini. Commit this file with the project; each build machine installs the selected packages in its own shared root. Windows uses:

[UCefView.XCefSDK.Win64]
Package=<package basename without .zip>
Sha256=<package SHA-256>

Linux uses [UCefView.XCefSDK.Linux]. Mac uses [UCefView.XCefSDK.Mac] with Package.arm64, Sha256.arm64, Package.x86_64, and Sha256.x86_64. Configure only the targets you use; universal Mac builds require both architectures. The settings panel lists packages for the current operating system.

Editor and game loading

Target Runtime source Build behavior
Editor, PIE, UnrealEditor -game Selected shared installation No SDK copy or cleanup, including Live Coding
Game Project-local Binaries/ThirdParty/XCef/<platform[/architecture]> Copies the selected SDK and stages loose NonUFS files

This behavior is the same for Engine and project plugins. Game builds require an installed SDK; UnrealBuildTool never downloads it. Packaged games use their staged files and do not depend on the shared cache or Editor SDK manager.

The shared SDK may be loaded by several Editors. Close all Editors using it before removing or modifying it. Close running games before updating their project-local runtime files.

Recovery and upgrades

  • Missing or mismatched SDK in Editor: install/select a compatible SDK in UCefView Settings, reinstall a damaged package if necessary, then restart. Recompiling the project does not repair a shared installation.
  • Missing SDK during game build: install the configured target package on the build machine, then build/package again. Distribute the full packaged output.
  • Older Editor copies: <Project>/Binaries/ThirdParty/Editor/XCef is no longer used or automatically cleaned. It can be removed after closing processes that might still use the old plugin.
  • Older forced startup builds: the plugin restores the saved preference from the previous workflow. New SDK selections only request a restart.

The .package record identifies the SDK payload. Game preparation clears the target runtime directory when this identity is missing or different; it preserves the directory when the identity matches. The record comparison is not a full file-content comparison.

Updating the plugin's XCef API version

Headers

Keep one cross-platform copy of the XCef public headers in Source/ThirdParty/XCef/include. UCefView includes these headers privately during compilation. Preserve the accompanying LICENSE. There is no XCef external module, import library, or bundled runtime in this source directory.

Runtime SDKs

Publish complete SDK archives for the supported operating systems and architectures. Update the fixed XCef version and release catalog in UCefViewEditor together with the plugin headers. Use a new XCef version when changing the interface; do not replace an existing version with incompatible binaries. Editor validates the XCef version, archive integrity, and required runtime files. It does not read the plugin headers.

Verification

After updating XCef, build and launch a project using UCefView, verify XCefHost startup and browser rendering, then verify packaged-game staging and startup on each supported platform.
